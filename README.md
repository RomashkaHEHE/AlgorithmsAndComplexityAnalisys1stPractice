## Алгоритмы и теоретические оценки

| Реализация | Лучшее время | Среднее время | Худшее время | Дополнительная память | Стабильность |
|---|---|---|---|---|---|
| BubbleSort с ранним выходом | Θ(N) | Θ(N²) для случайной перестановки разных ключей | Θ(N²) | Θ(1) | Стабильная |
| QuickSort, средний по индексу pivot | Θ(N log N) | Θ(N log N) при подходящей модели случайного входа | Θ(N²) | O(log N) стек в этой реализации | Нестабильная |

### BubbleSort

Соседние элементы меняются, если стоят в неправильном порядке.
После полного прохода максимум оставшейся части находится справа на окончательном месте;
граница `end` сдвигается влево. Если обменов не было, массив уже упорядочен.

Обратный массив из разных элементов требует `(N−1) + (N−2) + … + 1 = N(N−1)/2` сравнений и обменов.
Уже отсортированный массив требует `N−1` сравнений и ни одного обмена.
Стабильность сохраняется, потому что равные элементы не меняются местами (`>` вместо `>=`).

### QuickSort

Значение pivot берётся из середины текущего отрезка. Это **средний индекс, а не медиана значений**.
Два указателя ищут элементы, стоящие не с нужной стороны pivot, и обменивают их.
После разделения слева остаются значения не больше pivot, справа — не меньше; части сортируются отдельно.
При равных значениях указатели тоже сдвигаются, поэтому цикл завершается.

При сбалансированном делении `T(N) = 2T(N/2) + Θ(N) = Θ(N log N)`.
При последовательном крайне неравномерном делении получается `T(N) = T(N−1) + Θ(N) = Θ(N²)`.
Обратный и отсортированный массивы не дают такого случая автоматически при среднем pivot.
На массиве равных элементов данная двухсторонняя реализация тоже выполняет Θ(N log N) работы;
это не трёхстороннее разделение.

Рекурсивно обрабатывается **только меньшая часть**, большая продолжается циклом.
Размер очередного рекурсивного вызова не больше половины текущего отрезка, поэтому стек O(log N)
даже при худшем времени. Дополнительных массивов сама сортировка не создаёт.
QuickSort нестабилен: дальние обмены могут поменять порядок одинаковых ключей с разными метками.

## Методика измерений

1. Прогрев: 150 раундов на каждый из шести типов входов при N = 512 для обеих сортировок.
2. Для каждой точки создаётся исходный массив с фиксированным seed, затем две независимые копии.
3. Время измеряется через `System.nanoTime` **только вокруг вызова сортировки**.
4. Генерация, `clone`, эталонная сортировка, сравнение результата и запись CSV находятся вне замера.
5. Порядок BubbleSort/QuickSort чередуется между повторениями. Каждый результат сравнивается с эталоном.
6. Для девяти измерений считаются медиана и Q1–Q3; сырые значения сохранены без удаления выбросов.

Входы: случайные `int`, обратный, отсортированный, случайные значения 0–99, все равные,
почти отсортированный (около 1% **произвольных дальних обменов**, не соседних).

Ограничения: один процесс JVM, конечный диапазон N, фоновая нагрузка ноутбука, JIT/GC/кэш и шум таймера.
Прогрев не гарантирует полного завершения JIT-компиляции. На очень коротких запусках накладные расходы заметны.
Измерения показывают поведение этой реализации в этой среде, **не доказывают асимптотику** и не покрывают
специально построенный худший случай QuickSort. Для строгих микробенчмарков нужен JMH с независимыми fork.
